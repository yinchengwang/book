# Multimodal Expansion Phase A: Architecture Skeleton & Isolation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 构建可裁剪多模态数据库内核的架构骨架，实现编译时模态隔离、标准化引擎注册和统一执行层基础。

**Architecture:** 采用 6 层架构（接入层→统一执行层→分布式层→引擎适配层→存储层→公共基础设施）。本阶段重点建立 CMake 隔离机制和存储引擎 vtable 注册规范，为后续 Stream/Columnar 等新模态接入奠定基础。

**Tech Stack:** CMake 3.20+, C11, C++17, GoogleTest.

## Critical Findings from Codebase Analysis

> ⚠️ 以下发现需要在 Task 实现时额外处理：

1. **引擎注册未连接**：`storage_register_engine()` 仅在测试中被调用，内核启动时无自动注册机制。Task 3 必须确保 `engine_registry_init()` 在 `mm_storage_init()` 时被调用。

2. **Graph/Doc 引擎代码存在但未编译**：它们通过测试目录间接编译，不在 `storage/CMakeLists.txt` 中。Task 5 需要处理这些引擎的条件编译。

3. **cross_model_optimizer.c 需要更新**：第 300-325 行的 switch 不处理 `CROSS_MODEL_SPATIAL` 和 `CROSS_MODEL_TREE`。Task 2 必须同时更新此文件。

4. **func_registry.c 使用 MODEL_COUNT 作为哨兵**：`f->info.model == MODEL_COUNT` 表示"所有模型"。添加新枚举值后需要检查此逻辑。

5. **存在两份 mm_storage.h 副本**：`include/db/mm_storage.h` 和 `include/db/storage/mm/mm_storage.h` 内容相同，后续 Task 需要统一。

- [ ] **Step 2: Create engine_registry.c**

```c
// engineering/src/db/core/engine_registry.c
#include "db/engine_registry.h"
#include "db/multimodal_config.h"
#include "log.h"

// 引用各引擎的 ops 表（条件编译）
#ifdef MMDB_ENABLE_RELATIONAL
extern const storage_ops_t heap_engine_ops;
#endif
#ifdef MMDB_ENABLE_KV
extern const storage_ops_t kv_engine_ops;
#endif
// ... 其他引擎

int register_storage_engine(DataModel model, const storage_ops_t *ops) {
    return storage_register_engine(model, ops);
}

int engine_registry_init(void) {
    int count = 0;
    
#ifdef MMDB_ENABLE_RELATIONAL
    if (register_storage_engine(MODEL_RELATIONAL, &heap_engine_ops) == 0) count++;
#endif
#ifdef MMDB_ENABLE_KV
    if (register_storage_engine(MODEL_KV, &kv_engine_ops) == 0) count++;
#endif
    // ... 注册其他启用的引擎

    LOG_INFO("Registered %d storage engines", count);
    return count;
}
```
