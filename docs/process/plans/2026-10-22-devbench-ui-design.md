# DevBench 全新 UI 设计方案

> 日期：2026-10-22
> 适用对象：`apps/programmer-workbench`（DevBench · 程序员个人工作台）原生小程序重写
> 设计定位：**冷静的工具感** —— 不做消费级的活泼，也不做企业级的刻板。参考 Linear / Raycast 的气质：克制的色彩、精确的间距、清晰的层级。

---

## 1. 诊断：旧界面为什么"能用但不好用"

旧版是功能驱动的产物，问题不在配色好不好看，而在**信息层级与视觉编码失效**：

| 问题 | 具体表现 | 后果 |
|---|---|---|
| 导航语义重叠 | 5 个 tab 里「工作台」与「技术栈」都像"工作" | 用户点开前不知道去哪 |
| 首屏浪费 | 顶部一张大渐变卡（问候+座右铭+4 统计）占约 1/3 屏 | 信息密度低，真正的待办被挤到第二屏 |
| 入口无优先级 | 8 个快捷入口等权平铺 | 高频操作和低频操作一样难找 |
| 视觉不统一 | 内联样式散布约 470 处，同一"卡片"在不同页圆角 16/20/24/32 混用 | 像 18 个不同人做的 18 个页面 |
| 图标风格杂糅 | emoji 当图标（🩷 🪙 🐿️ 与几何图形混排） | 大小、基线、色相都不齐 |
| 字阶过多 | 5~6 级字号，22/24/26/28/32/40/44rpx 都在用 | 层级反而模糊 |
| 语义色缺失 | 优先级只靠文字"高/中/低"，无视觉编码 | 扫视时读不出重点 |

---

## 2. 设计原则

1. **首屏即状态** —— 「今日」页必须在 3 秒内回答"今天什么情况"，无需滚动。
2. **捕获优先于整理** —— 最高频动作是"记一下"，不是"翻找"。任意页面可唤起捕获浮层。
3. **拇指优先** —— 主操作落在屏幕下三分之一；FAB 与 tabBar 构成操作锚点。
4. **色即语义** —— 品牌色只用于"选中态 / 主操作 / 关键数字"，一屏最多一个强调点；其余色彩必须承载信息（优先级、状态、分类）。
5. **靠描边分层，不靠阴影** —— 深色模式下阴影本就不可见，用 0.5px 描边建立层次更可靠。
6. **克制到近乎无聊** —— 不做装饰性渐变、不做无意义动效。工具的价值是可靠，不是惊喜。

## 3. 设计语言

### 3.1 色彩

中性骨架偏冷（slate 系），不使用纯灰，避免发闷。

| 语义 | 浅色 | 深色 |
|---|---|---|
| 页面底 | `#F7F8FA` | `#0B0F17` |
| 卡片 | `#FFFFFF` | `#151A23` |
| 内嵌块 | `#F1F3F5` | `#1D2430` |
| 描边 | `#E4E7EC` | `#232B38` |
| 主文 | `#0F172A` | `#E6EAF0` |
| 次文 | `#64748B` | `#94A3B8` |
| 品牌 | `#0284C7` | `#38BDF8` |
| 危险 | `#E5484D` | `#E5484D` |
| 警告 | `#F5A524` | `#F5A524` |
| 成功 | `#30A46C` | `#30A46C` |
| 辅助 | `#7F77DD` | `#7F77DD` |

深色底色用 `#0B0F17` 而非纯黑 `#000`，减少纯黑与亮字的极端对比带来的眼疲劳。

### 3.2 字阶（只有四级）

| 级别 | 字号 | 字重 | 用途 |
|---|---|---|---|
| display | 22px | 500 | 关键数字，强制 `tabular-nums` |
| title | 17px | 500 | 页面标题、卡片标题 |
| body | 14px | 400 | 正文、列表项 |
| caption | 12px | 400 | 时间、标签、辅助说明 |

字体：UI 用系统无衬线（`-apple-system` / `PingFang SC`），代码用 `ui-monospace` / `Menlo`。

**只有两个字重：400 与 500。** 不用 600/700 —— 中文在小字号下加粗会糊。

### 3.3 间距与圆角

- 间距基准 4px：`4 / 8 / 12 / 16 / 24`
- 页面左右留白 16px
- 圆角三档：卡片 12px、控件 8px、胶囊 999px（不再混用四种）
- 最小点击区 44×44px

### 3.4 图标

- **UI 控件**：1.2~1.4px 线性图标，统一 16/18px，`stroke` 继承 `currentColor`
- **工具入口**：圆角方块 + 等宽符号（`{}` `64` `://` `ID` `.*` `#`），开发者语感，零图片资源
- **内容标识**：允许保留少量 emoji，但仅出现在用户数据里（如分类标签），不用于 UI 控件

## 4. 信息架构

5 个 tab，全部保留原有功能，只做**重命名 + 重新归位**：

| Tab | 原名称 | 下属模块 |
|---|---|---|
| **今日** | 工作台 | 待办清单 · 状态总览 · 心情打卡 · 项目集/闪念入口 |
| **技术** | 技术栈 | 技术笔记 · 代码片段 · 面试题库 · 资源收藏 |
| **生活** | 生活 | 读书进度 · 健身记录 · 心情日记 · 日程安排 |
| **工具** | 工具箱 | 十个离线工具 |
| **我的** | 我的 | 个人资料 · 主题外观 · 备份恢复 |

改名理由：「工作台」→「今日」把 tabBar 从"功能分区"读成"时间轴"，用户一眼知道这是"现在要看的东西"。

**全局捕获浮层**：任意页面 FAB 唤起，三个快捷动作 —— 新建待办 / 记闪念 / 写笔记。这是对"捕获优先"原则的落地，也是旧版最大的缺失（旧版要先想"这属于哪个模块"再导航）。

## 5. 关键页面

### 5.1 今日页

自下而上组织，拇指热区优先：

1. **头部**（小）：日期 + 星期 / 问候语 / 设置入口。去掉大渐变卡。
2. **今日待办**：最多显示 3 条，行内可勾选；超额显示"还有 N 项"。右端 6px 圆点编码优先级（红/琥珀/绿）。
3. **状态带**：4 个等宽指标（笔记 / 在读书 / 本周运动 / 连续天数）。数字用 display 级，`tabular-nums` 防跳动。
4. **心情打卡**：一行 5 个圆点，点一下即完成当日打卡 —— 降低记录成本，提升留存。
5. **快捷入口**：收敛到 4 个高频（笔记 / 片段 / 闪念 / 日程），其余走 FAB 或对应 tab。

### 5.2 列表卡范式（18 页通用）

```
┃ 标题                    相对时间
┃ 分类 · 标签
```

- 左侧 3px 色条承载优先级/分类语义，不额外占空间
- 标题单行截断，摘要单行截断
- 整卡可点，**卡内不放独立按钮**，避免误触
- 已完成项：文字加删除线 + 降为次文色

### 5.3 工具箱

- 顶部搜索框，输入即过滤（10 个工具靠平铺也能扫，但有搜索更快）
- 4 列网格，图标 + 名称
- 点选后展开**全屏面板**（不增加页面数，用 `wx:if` 全屏层实现）：输入区在上、结果区在下、结果一键复制
- 旧版是"同页切换面板"，手机屏小导致切换后要滚动才能看到结果

## 6. 交互与动效

| 场景 | 处理 |
|---|---|
| 列表项按下 | `scale(0.98)` + 背景加深，150ms |
| 待办勾选 | 圆点填充品牌色 + 文字划线 + 降色，200ms |
| 数字变化 | **不加动画**（工具感，动画反而干扰读数） |
| 页面切换 | 用原生转场，不自造 |
| 空状态 | 图标 + 一句说明 + 一个主操作，不留纯空白 |

---

## 7. 易用性硬指标

- 正文对比度 ≥ 4.5:1，次要文字 ≥ 3:1
- 所有可点元素 ≥ 44×44px
- 深色模式不使用纯黑底、不使用纯白字
- 所有数字用 `tabular-nums`，避免动态数值抖动
- 表单输入聚焦时字段标签不消失（不做浮动标签，小程序里易错位）
- 危险操作（清空数据、删除笔记）必须二次确认，且确认按钮用危险色

## 9. 原生小程序实现要点

设计要落地，必须适配原生框架的硬约束：

1. **CSS 变量作用域**：WXSS 不支持 `[data-theme]` 属性选择器。改用 class 承载变量（`.theme-light` / `.theme-dark`），挂在每页根 view 上。
2. **主色可换**：通过根 view 行内 `style="--brand: {{primaryColor}}"` 覆盖。若真机变量继承不稳定，退化为 5 个预设 class（`.brand-sky` / `.brand-violet` / …）。
3. **自定义 tabBar**：原生 tabBar 无法加选中指示条、无法做圆角悬浮。若要完整实现本设计的 tabBar，需 `custom: true` + 自建组件。**取舍**：首版用原生 tabBar（纯文字 + 品牌色选中态），保证零风险；后续再升级为自定义。
4. **原生组件层级**：`textarea` 是原生组件，会盖住弹层。笔记编辑的 Markdown 预览用页面内状态切换（不用弹层），天然规避。
5. **图标零资源**：全部用内联 SVG（`background-image: url("data:image/svg+xml,...")`）或 CSS 几何图形，不引入 PNG。
6. **滚动**：tab 页用页面级滚动；子页长列表用 `scroll-view` 并显式设高，避免双滚动条。

---

## 10. 不做什么

- 不做装饰性渐变、玻璃拟态、霓虹光效
- 不做自定义字体（加载成本 + 首屏闪烁）
- 不做骨架屏（本地数据读取在毫秒级，骨架屏反而制造等待感）
- 不做动画图表（工具页要的是读得准，不是看着炫）
- 不引入任何 UI 组件库（原生 + WXSS 足够，也避免构建链）
